- [minor] src/main/java/com/marketdata/sdk/options/ExpirationFilter.java:113 — record Dte(String value) has no compact constructor, so a consumer can bypass all factory validation via `new ExpirationFilter.Dte(...)` (the record and its canonical constructor are implicitly public as a nested type of a public interface). Widening the backing type from int to a free-form String makes this loophole materially worse than before: a directly-constructed Dte can now carry any malformed string (e.g. "30--45", empty, or stray characters) straight onto the wire, and `new Dte(null)` would be silently dropped by RequestSpec.Builder#query's null-skip rather than erroring, unlike the non-negative/range/non-empty guarantees the static factories advertise. Consider a compact constructor requiring non-null/non-blank value, consistent with OnDate's existing Objects.requireNonNull guard.
